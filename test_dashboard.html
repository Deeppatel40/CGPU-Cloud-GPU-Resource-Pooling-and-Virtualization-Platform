Contract Summary (Next.js Portal ⟷ Go API Gateway)

All endpoints accept and return JSON. The client provides request_id (UUIDv4) on submission for idempotent retries.

Method Endpoint Primary Purpose Key Input / Constraints Key Output
POST /api/v1/jobs Submit workload request_id, name, workload_id, requested_vram_mib (>0) 201 Created (or 200 OK if retried) with Job ID
GET /api/v1/jobs Job History status, workload_id, page, limit Paginated job summaries list
GET /api/v1/jobs/{job_id} Status & Telemetry job_id path param Lifecycle state, placement node, live GPU metrics, failure diagnostics
DELETE /api/v1/jobs/{job_id} Cancel workload job_id path param Releases GPU VRAM allocation immediately
GET /api/v1/jobs/{job_id}/logs Log Stream tail, stream=true (SSE) Structured stdout/stderr logs
GET /api/v1/jobs/{job_id}/artifacts Artifacts & Checkpoints job_id path param List of saved model weights, .pt checkpoints, sha256 hashes
GET /api/v1/gpus GPU Pool Inventory None Nodes, GPUs, total/allocated/free VRAM, active allocations

🤝 Scheduler Placement Handoff (Deep Patel & Nishit)

The Go API submits unplaced jobs to the CGPU Placement Engine. The scheduler returns:

Field Type Example Role
assigned_node string wsl-worker-rtx4050-01 Target Kubernetes worker node
assigned_gpu_id string gpu-nv-rtx4050-c89b3f Target GPU hardware instance
quota.allocated_vram_mib int 2048 VRAM slice quota in MiB
quota.enforcement_mode string CGPU_VIRTUAL_CGROUP Isolation & cgroup memory limit
placement_reason string BEST_FIT_PACKING_FOUND Placement explanation when status == PLACED
pending_reason string WAITING_FOR_CAPACITY Explanation when status == PENDING
